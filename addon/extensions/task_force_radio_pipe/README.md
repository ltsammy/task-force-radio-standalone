# `task_force_radio_pipe` — Arma 3 extension (TFRS)

Extension DLL for Task Force Radio Standalone. It replaces the original shared-memory bridge to
the TeamSpeak 3 plugin — mic capture, Opus encode/decode, UDP networking, playback mixing, and the
radio DSP effect chain all live in this DLL, talking directly to `voice-server` over UDP. There is
no separate client process to install or update.

* **Upward (SQF):** byte-compatible with [`docs/protocol-extension-legacy.md`](../../../docs/protocol-extension-legacy.md).
  `addon/addons/` is unchanged.
* **Downward (voice server):** [`docs/protocol-network.md`](../../../docs/protocol-network.md) — a
  native, byte-exact client of `voice-server`'s existing UDP protocol.
* **Audio DSP:** [`docs/dsp-audio-pipeline.md`](../../../docs/dsp-audio-pipeline.md) — filter
  formulas, panning, gain staging; section 6 covers the `State` ↔ `Voice/` module split.

## Building

```bash
# 64-bit (task_force_radio_pipe_x64.dll)
cmake -S . -B build/x64   -A x64
cmake --build build/x64   --config Release

# 32-bit (task_force_radio_pipe.dll)
cmake -S . -B build/win32 -A Win32
cmake --build build/win32 --config Release
```

Output: `build/<arch>/Release/task_force_radio_pipe[_x64].dll`. Both DLLs belong in
`@task_force_radio/` (Arma automatically loads the matching architecture). CI (`.github/workflows/addon.yml`)
builds both architectures on every push; `../build-local.ps1`/`../publish-local.ps1` pull those
artifacts down and build/publish the PBOs locally (PBO building needs a P-Drive or a real Arma 3
install, which GitHub-hosted runners don't have).

Requirements: CMake ≥ 3.16, MSVC (Visual Studio 2019/2022). One vendored dependency,
[`third_party/opus`](third_party/opus) (upstream libopus, pinned to `v1.6.1`, plain committed
source copy pruned to just what our CMake build touches — no `dnn`/`tests`/`training`/autotools
files). Everything else is dependency-free (no `FetchContent`, no system DLLs beyond what Windows
itself ships — WASAPI/COM via `Ole32`, Winsock via `Ws2_32`, SHA-256 via `Bcrypt`).

The CRT is linked **statically** (`CMAKE_MSVC_RUNTIME_LIBRARY = MultiThreaded`) so players without
the VC++ redistributable can still load the DLL.

## What's implemented

**Legacy protocol:** sync/async determined solely by the trailing `~`; `POS`/`FREQ`/`TANGENT`/
`SPEAKERS`/`SETCFG`/`KILLED`/`RELEASE_ALL_TANGENTS`/`RadioTwrAdd`/`RadioTwrDel`/`DFRAME`/
`MISSIONEND` all implemented per `docs/protocol-extension-legacy.md`. `TS_INFO PING` reflects the
real `VoiceNetworkClient::isConnected()` state; `SERVER`/`SERVERUID`/`CHANNEL` are fixed string
literals (no channel concept in the native relay). Additive, non-legacy commands: `UID` (real
`getPlayerUID` for nickname↔uid resolution), `MICPTT`/`MICMUTE`/`SPEAKERMUTE` (CBA keybinds, see
`fnc_initKeybinds.sqf`).

**Audibility solver → native playback:** `State::computeAudibleUnits()` runs every tick;
`Extension.cpp` resolves each unit's uid to a voice-server session and pushes gain/azimuth/effect
into that session's `RemoteVoiceSource`. Radio transmit state (`sendRadioTx`/`setRemoteTx`) refreshes
every tick, not just on change — the receiving side's 1.5s expiry depends on that steady stream to
self-heal a single dropped UDP packet.

**Settings:** server host/port/password, mic/speaker volume, VAD threshold, and transmit mode are
CBA_Settings (`fnc_initCBASettings.sqf`'s `TFAR_Voice_*` entries), relayed via the same `SETCFG`
mechanism every other TFAR setting uses. No in-game audio device picker — always resolves the OS
default communications device.

**Geometry/audio control values:** `docs/dsp-audio-pipeline.md` documents the actual formulas
(distance attenuation, panning, radio distortion per type, antenna loss); nothing here duplicates
that.

## Deliberate simplifications / open items

| Topic | Status |
|---|---|
| **One row per UID** | `computeAudibleUnits()` reports exactly **one** source per speaker: whichever has the highest `gain` (direct / radio / speaker / intercom). Only audible if you hear someone simultaneously via direct speech *and* radio. |
| **Resampling** | Linear interpolation (capture-side downmix/resample, playback-side device-rate conversion), not a windowed-sinc resampler — adequate for voice, disclosed as a deliberate simplification (matches this project's existing precedent for e.g. `Panning.h`'s HRTF stand-in). |
| **No device picker** | Always the OS default communications device (`eMultimedia`, not `eCommunications` — avoids the legacy Recording Devices panel silently pointing elsewhere). |
| **`stereoMode`** | Parsed and stored from `FREQ` but not currently applied to playback. |
| **Radio beep coverage** | The start/stop click plays for `digital`/`digital_lr`/`airborne`/`dd` radio subtypes (the four families that had dedicated clips in the original TS3 plugin); phone/speaker/intercom/direct speech have no beep, matching original scope. A transmission that ends via silent 1.5s timeout (dropped last packet) rather than an explicit release doesn't play its end beep — see `VoiceSession.cpp`'s `onRadioTx`. |
| **`RVExtensionVersion`** | Only `RVExtension` is exported, no `RVExtensionVersion`/`RVExtensionArgs` — carried over from the original; nothing on the SQF side depends on it. |

## Manual testing without a full Arma session

A minimal host is enough to exercise the command parser (the DLL only needs `RVExtension`):

```cpp
// LoadLibraryW(L"task_force_radio_pipe_x64.dll"); GetProcAddress(h, "RVExtension");
char out[10240];
fn(out, sizeof(out), "TS_INFO\tPING");             // "PONG" once voice-server connects, else empty/timeout
fn(out, sizeof(out), "POS\tFoo\t[0,0,0]\t[0,1,0]\ttrue\ttrue\ttrue\t0\tno\t0\t1\t0\tfalse\tfalse~");
                                                    // "OK" (or "Not connected to TeamSpeak" until voice-server connects)
fn(out, sizeof(out), "IS_SPEAKING_BULK\tFoo\tBar"); // "00\t00\t"
fn(out, sizeof(out), "DFRAME~");                    // "NEEDCFG" the first time
fn(out, sizeof(out), "MISSIONEND~");                // ""
```

Diagnostics log to `%APPDATA%\Tfrs\Extension\extension.log` (connection attempts, capture/playback
device init, config state) — the primary tool for debugging a live connection issue without
rebuilding.
